# 6.3.0

Planning declares which acceptance criteria need live interaction evidence. From Super Awesome Games ticket
VGD2A04892DB-34 (2026-11-12): QA spent 45 minutes probing audio internals on a spike whose criteria only asked for a
record of observations, because nothing told it which criteria needed live testing.

- Executable tasks carry `interactionCriteria` (`CSweet.Agent.SDK.VideoGame.Contracts` 1.2.0): zero-based indexes of the
  task's own acceptance criteria that need behavior observed in the running build (input, gameplay, audio, UI). The
  Producer records them as a `browser-interaction` verification, and QA 5.7.0 requires live evidence for those only.
- Fresh task indexes are validated: indexes must be distinct, name the task's own criteria, and need
  `browserVerification` canvas or page. An empty list is stored as absent, so proposal JSON is unchanged for tasks
  without interaction criteria. Retained indexes are not revalidated.
- The planning policy asks for investigations whose deliverable is a record of observations to be planned as
  `video-game.research-spike.v1`.

Depends on video-game contracts 1.2.0 (publish first). SDK unchanged (5.23.1).

Validation: `dotnet test` 237 passed, 0 failed, built against locally packed contracts 1.2.0. Not yet run live.
