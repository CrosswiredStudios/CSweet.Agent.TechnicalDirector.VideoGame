# 6.2.0

Fixes a review loop seen at Super Awesome Games on 2026-11-10. Ticket #22's code was approved on the first technical review, yet the ticket went back to the engineer. The plan's browser rule ("Browser-visible increments require early real Chromium launch and retained screenshot…") existed only as constraint prose copied onto every ticket. The engineer's agent, this reviewer and QA each decided from different text whether a ticket needed browser evidence.

## Planning declares browser evidence per task

- Every freshly generated executable task now carries `browserVerification`: `canvas` (acceptance needs the running game scene), `page` (other browser-visible output) or `none` (no runnable browser output changes, such as dependency pins, tooling or documents). The planning schema offers exactly these choices and a task index without them is corrected before it is accepted.
- The Producer records the choice on the ticket as `WorkItemPlanningSpecification.Verifications` (contracts 5.4.0), which the engineer, the reviewer and QA all read.
- The planning policy asks for the field and tells the model not to restate browser rules in technical constraints or criteria.
- The synthesized Phaser pin task is `none`; it no longer inherits the browser choice of the task it is copied from.
- Task indexes retained from before this release are accepted unchanged; their tickets are recorded as undeclared and agents keep their previous rules for them. The new field is omitted from JSON when absent, so retained planning digests do not change.

## Technical review checks the declaration in code

Through `CSweet.Agent.SDK` 5.20.0 (`BranchDiffTechnicalReview`), before any model call:

- Declared browser-smoke with no passing receipt in the author's validations: rejected with one finding that names the exact receipt (`node .csweet/browser-smoke.cjs <build directory>` plus `--canvas` when required).
- Receipt present: the reviewer is told the requirement is satisfied and not to reject for missing browser evidence.
- Declared none: the reviewer is told not to require Chromium launches or screenshots.
- Undeclared (older) tickets: unchanged.

Uses `CSweet.WorkManagement.Contracts` 5.4.0 (was 5.3.0) and `CSweet.Agent.SDK` 5.20.0 (was 5.14.0). Publish both first.

Validation: not yet run. Written without a .NET SDK available; run `dotnet test` and the published output's `--self-test` before publishing. New tests: `BrowserVerificationPlanningTests`; `DependencyPinPlanningTests` extended.
