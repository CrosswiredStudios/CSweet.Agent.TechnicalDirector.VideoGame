# 6.2.1

Moves to `CSweet.Agent.SDK` 5.22.1 (was 5.20.0). No agent code changed. No manifest, capability, grant or configuration change.

**6.2.0 was never published** (there is no `v6.2.0` release tag). Two `ProgressivePlanningTests` used a task-index fixture without the `browserVerification` field that 6.2.0 made required for fresh task indexes, so the scripted reply was rejected, both tests fail at that commit, and the release build stops at `dotnet test`. The fixture now declares it (`canvas` for the engineering task, `none` for the other). No agent code changed for this; the 6.2.0 changes (per-task browser evidence in planning and technical review, see `6.2.0.md`) ship for the first time in 6.2.1.

What the agent gets from the SDK:

- **5.22.1, progress can no longer stop work.** A progress report that fails no longer uses up its sequence number; it is resent with the same number. A failed "LLM request received / queued / generating" status report no longer fails the model call. On 2026-11-11 at QFN Games one lost progress report made the next model call fail with "Progress sequence numbers must be strictly monotonic without gaps" and blocked the Engineer's ticket.
- **5.22.0, a saved result is never retried.** When the platform completes a call but its result cannot be read as the expected type, the call fails as a non-retryable `platform.contract_violation` that says the action already happened, instead of a generic invalid-JSON failure. A result the platform flags as breaking its own output schema, but that still reads, is used.
- **5.21.0 and 5.21.1** add `AgentModelJson` (model JSON replies corrected in the same conversation) and reading JSON followed by trailing reasoning text. This agent does not call them yet.

C-Sweet itself also accepts progress gaps and resent reports and returns committed results marked instead of failed, so these failures are already prevented for older agent versions once the AgentHost is updated; this release adds the agent-side behavior.

The contract-violation handling matters most here: on 2026-11-11 this agent's `request_project_resource` call saved the build-capacity request but was reported as failed, and it retried 12 times.

Tests: 235/235 pass against SDK 5.22.1.
