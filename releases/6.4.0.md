# 6.4.0

Planning declares observed behavior, and technical review requires the shared scenario run for it.

From Super Awesome Games ticket VGD2A04892DB-38 (2026-11-13). Ticket 34's outcome was "a committed observation record
for a normal latest-Chromium run" of five game scenarios, yet it declared only `browser-smoke`. The planning prompt told
the model that a record of observations "is judged on that record", so no criterion asked for observed behavior. The
record then carried values reasoned from source, and QA rejected it twice, one mismatch per round.

- **Planning.** `interactionCriteria` now covers every criterion about behavior in the running build and every criterion
  a record of a run must report. A recorded observation is only as good as the run behind it. A pure research note
  that observes no build of the project stays a `video-game.research-spike.v1` deliverable without interaction criteria.
- **Technical review (CSweet.Agent.SDK 5.25.0).** When interaction is declared, review requires a passing
  browser-scenarios receipt (`node .csweet/browser-scenarios.cjs <build> [--record <path.md>]...`) in addition to the
  smoke receipt. The model is asked whether each check measures its criterion from emitted events and whether every
  computed invariant is checked.
- **Packages.** `CSweet.Agent.SDK` 5.25.0 and `CSweet.WorkManagement.Contracts` 5.6.0.

Validation: `dotnet test` 237 passed, 0 failed.
