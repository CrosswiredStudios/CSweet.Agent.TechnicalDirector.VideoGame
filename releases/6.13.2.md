# 6.13.2

Fixes roadmap generation failing with "Page failed after three attempts: approved outcomes and constraints".

- When Victor lists approved commitments, every entry must cite an accepted source. Entries that cite none are now reported to the model together, with the instruction to cite them or remove them. Previously one was named per attempt, so a reply with four of them ran out of attempts while it was still improving.
- If some entries still cite no accepted source on the last attempt, they are left out and recorded on Victor's timeline, and the roadmap continues with the cited commitments. These were restatements of manager direction about asset fallback, which is carried separately. An inventory with nothing citable still fails.
- Victor is told that manager directions, resource notes and other conversation context are not commitments.
- When a roadmap contains several Epics that own only constraints, they are all named in one correction.
- Each correction sent to the model now repeats the corrections from earlier attempts, so fixing the latest problem does not undo the previous fix.

Existing projects keep their accepted roadmap. A project whose roadmap generation failed regenerates it when the Producer requests it again (Producer 6.22.1).

Validation: 255 regressions, including the recorded uncited-commitment reply shape.
